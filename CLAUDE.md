# AirborneNX

Порт Xbox 360 версии Medal of Honor: Airborne на Nintendo Switch (homebrew) через статическую перекомпиляцию
PowerPC → C++ → AArch64. Пользователь общается на русском — отвечай по-русски.

Перед началом работы прочитай `docs/ASSESSMENT.md`: там текущая оценка и принятый план.

## Окружение

- Windows, рабочая папка `D:\Games\AirborneNX`. Скрипты — Python и PowerShell.
- Тулчейны лежат локально (не в git): `tools/toolchain/llvm-mingw-*` (хост Windows),
  `tools/toolchain/nx-sdk` (devkitA64/libnx), `tools/toolchain/venv` (Python).
- Не в git (см. `.gitignore`): файлы игры (`[XBOX360]*`, `extracted/`), `generated/`, `dist/`,
  сторонние исходники (`tools/XenonRecomp`, `tools/XenosRecomp`, `tools/mesa-switch`, `tools/reference-nfsmw`),
  сырые логи. **Никогда не коммить ассеты игры, `default.xex` и производные от них бинарники.**

## Направление работы

Текущий рантайм (`runtime/`, XenonRecomp) — тупиковая ветка: графика обрабатывает только заранее
«опознанные» отрисовки. Принятый план — переход на ReXGlue SDK из `tools/reference-nfsmw/sdk`
(порт NFS:MW на Switch) по его `docs/porting-another-game.md`:
1. игра доходит до меню и уровня **на PC** с эмуляцией Xenos;
2. сборка под Switch со слоем SDK;
3. замеры, затем собственный рендер.
Из старого кода переносить только проверенное: таблицы переходов, перехват часов XDK, упаковку SD, сведения
из аппаратных логов.

## Правила работы

- **Экономь лимиты.** Атомарные правки кода (одна функция/файл, понятная спецификация) поручай субагенту
  `implementer` (Sonnet). Механическое — переименования, поиск по логам, сводки, правка конфигов — `scout` (Haiku).
  Сам занимайся архитектурой, диагностикой и ревью результата субагентов.
- **Тесты — только по делу.** Не плодить тесты, отчёты и JSON-«progress» файлы. Тест пишется, когда он ловит
  реальную ошибку, которую иначе не найти дешевле. Никаких сводок с «миллионами исполнений».
- **Логи.** Не логировать каждый вызов ядра. Сэмплирование и счётчики, подробности — только при ошибке.
- Коммиты небольшие и осмысленные; не плодить нумерованные копии сборок/папок — история в git.

## Сборки и проверка на Switch

- Публиковать в `dist/switch/airborne-nx/airborne-nx.nro` и `dist/airborne-nx.zip`; версия/ID сборки —
  в метаданных и логах, не в именах папок и файлов. Каталог с контентом `airborne-nx/game` переиспользуется.
- Лог с консоли — `result.txt`. Меньше поездок PC↔Switch: проверки группировать в одну сборку.
- Сбой на железе логирует операцию, код результата, адреса/размеры, состояние памяти и ID сборки; первая
  ошибка сохраняется. Различать failed/blocked/skipped/passed. Не заменять измеренный результат непроверенным.
- Подробности платформы Switch/NVK: `tools/reference-nfsmw/docs/platform-notes.md`.
