AirborneNX — общая диагностика старта, версия 0.3
================================================

Это диагностическая сборка для порта Medal of Honor: Airborne, не игра.
Повторять старые CPU probe v0.1 и memory probe v0.2 не нужно.

1. Скопируй папку switch из архива в корень SD-карты.
2. Запусти AirborneNX Startup Probe через hbmenu в режиме приложения,
   в котором прошёл CPU probe. NRO и image.bin должны лежать рядом.
3. Дождись RESULT=PASS или RESULT=FAIL, затем нажми +.
4. Пришли один файл /switch/airborne-nx-startup-v0.3/result-v0.3.txt.
   Если приложение упало, пришли оставшийся неполный лог и код ошибки.

За один запуск проверяются:
- два нативных рабочих потока, TLS и изоляция состояния округления;
- события с ручным и автоматическим сбросом, таймауты, завершение потоков;
- ход 50-МГц гостевого таймера относительно ожидания;
- свободный виртуальный диапазон 4 ГиБ и требуемые syscall-возможности;
- исправленное отображение образа игры и гостевого стека через staging;
- контроль SHA256 образа и 768 прямых вызовов настоящей функции игры;
- ещё 256 вызовов этой функции в двух потоках с отдельными гостевыми
  стеками, значениями R13 и служебными ячейками памяти;
- физические окна A/C/E: согласованность скалярных, векторных,
  атомарных обращений и очистки строки кэша;
- 4 МиБ гостевой heap-памяти: нулевая инициализация и двусторонняя
  видимость записей на каждой из 1024 страниц;
- защитные промежутки, отклонение неверных запросов, снятие отображений.

Независимые этапы продолжаются после локального отказа. Отказ образа
не отменяет проверку физической памяти и heap. Нативные потоки и события
проверяются до отображения гостевой памяти. Если рабочий поток не завершится
за ограниченное время, приложение запишет ошибку и завершит процесс.

Один result-v0.3.txt содержит Build ID, окружение, параметры отображений,
состояния регионов, коды ошибок, первую ошибку и результаты этапов.
CHECKS=1569 относится к унаследованным проверкам leaf/физических инструкций;
heap и рабочие потоки имеют отдельные счётчики в строках HEAP/SERVICE.
RESULT=PASS означает прохождение включённых диагностических проверок.
Строка game_entry=BLOCKED ожидаема: полная точка входа игры пока не запускается.
Проверка сохранения R13 не заменяет реализацию полного гостевого PCR/TLS ABI.

4 ГиБ — виртуальный диапазон, не расход RAM. Образ, heap и гостевые стеки
занимают около 24 МиБ плюс расходы NRO/библиотек. При ошибке снятия
отображений приложение после + завершает процесс целиком.
Компиляция и линковка проверяются на ПК; исполнение на Switch ещё не проверено.
