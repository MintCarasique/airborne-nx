AirborneNX 0.7.1 — исправление остановки перед загрузкой ролика

В журнале 0.7 запуск остановился на viOpenDefaultDisplay/vblank с кодом
0x1272 (4722). До чтения файлов игры и отрисовки ролика дело не дошло.
Чёрный экран был первым буфером инициализации; ролик на Switch не проверен.

Исправлено владение дисплеем: ожидание vblank использует дисплей, уже открытый
libnx для стандартного окна. Повторного открытия нет; код игры закрывает только
своё событие ожидания. Дисплей закрывает его владелец, libnx, при завершении.
Логика владения проверяется локально, перенаправление вызовов — в готовом ELF.
Это ещё не подтверждение воспроизведения ролика на Switch.

Обновление без повторного переноса игровых ресурсов:
1. Распакуйте switch из ZIP в корень SD. Появится отдельная папка
   /switch/airborne-nx-entry-v0.7.1. Старую папку 0.7 оставьте на месте.
2. Ресурсы будут взяты из /switch/airborne-nx-entry-v0.7/game автоматически.
   Альтернативно поддерживается game внутри новой папки. Переносить 6,4 ГБ
   повторно не нужно. Выбранный путь и три обязательных файла проверяются
   перед запуском и записываются в журнал.
3. Запустите 0.7.1 через hbmenu в режиме приложения (R при запуске игры).
   Один запуск ограничен 120 секундами. После остановки и очистки нажмите +.
   При HOME_REQUIRED закройте приложение через HOME.
4. Пришлите result-v0.7.1.txt из новой папки и сообщите, появилось ли движущееся
   изображение. Старые отдельные проверки CPU/памяти повторять не нужно.

На ПК получены 253 кадра вступительного ролика через настоящий игровой код
и Vulkan. Сохраняется известная остановка на XMADisableContext при инициализации
звука; клип может прерваться. Меню/игровой процесс пока не подтверждены.
Версия 0.7.1 на Switch ещё не запускалась. Аппаратные результаты и файлы 0.7
сохранены отдельно. Контрольные суммы новой сборки — SHA256SUMS.txt.
