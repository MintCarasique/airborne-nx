# Resource loading after XNet bootstrap

The real Windows guest entry now reads `D:\MOHAGame\Xbox360TOC.txt` (78,447 bytes) and `D:\MOHAGame\Config\Xenon\Cooked\Coalesced.ini` (308,494 bytes) from the extracted Xbox 360 game. Both reads return their full requested size. Exact file/trace hashes and the current cross-build identity are recorded in `resource_loading_progress.json`.

This path adds XNet parameter registration, ANSI string construction, bounded module/resource lookups, the requested disabled FPU-exception state, supported NTSTATUS/DOS error translations, file metadata/open/read/close, and memory statistics from live allocator accounting. XNet registration stores configuration; it does not implement secure networking, Xbox Live or socket traffic. Unimplemented network calls still stop.

`D:`, `game:` and `dvd:` map to one read-only content root. Path components match ASCII case without selecting ambiguous aliases; parent traversal is rejected. Missing optional shader-dump paths return an actual not-found result. There is no fabricated TOC/config fallback. Writes, directory handles, relative handle paths and asynchronous file/APC completion are not implemented. File seeks use 64-bit offsets. Statistics describe the 512 MiB virtual Xbox budget, not free physical RAM on Windows or Horizon; image, stack, runtime metadata, physical allocations and committed virtual regions are charged against it. Guest paging/cache categories without a corresponding emulated allocation remain zero.

On Switch, the content root is `<NRO directory>/game`; a later meaningful package must arrange the original game data there. Existing 0.6 packages have not been changed and do not contain this new data layout or runtime. No new hardware transfer is requested now.

Loading configuration triggers a second ring initialization. A drained, healthy queue can now be rebound with pointers/writeback reset while register/shader state persists. Busy/suspended/failed queues cannot be rebound. The guest subsequently reaches a new point draw (`00010081`, mode 4) and stops before retiring it because a native Vulkan pipeline/resource binding is still missing. The queue has retired 1,960 packets. This draw is not evidence of menu or scene rendering.

The final vertex program is 24 words and generates a fixed position/interpolator without vertex fetches; the pixel program is 9 words. Their reconstructed interfaces compile to SPIR-V and pass `spirv-val --target-env vulkan1.2`. This does not establish rendering equivalence. The complete register/shader snapshot is retained privately under `generated/captures/post-config-draw.json`; `post_config_shader_translation.json` records hashes and validation. Frozen initial-clear shader proofs were not overwritten. Draw diagnostics now recognize that a texture fetch occupies all six descriptor words, preventing texture words from being misread as an invalid vertex-buffer address.

The host also exposed an existing error-path issue: an ordinary C++ runtime exception could unwind guest mappings while native guest workers were still alive, causing a secondary access violation. The bounded-entry handler now handles all standard exceptions before guest-memory teardown and reports the original ring error. Debugger logs preserve the secondary-fault investigation; the final actual run stops normally at the named unsupported draw with exit 10 and logs device/file cleanup.

Validation: 1,323 service checks, including asset open/read-only enforcement, metadata, seek beyond 4 GiB, EOF and closed-handle errors, actual file bytes, allocator-accounting totals and network configuration lifecycle; 48 PM4/MMIO checks, including busy/healthy ring rebinding and texture descriptor diagnostics. The revised full AArch64 runtime compiles and links successfully; no execution of these changes on Switch is claimed. Windows audio submits PCM frames during startup, but their presence does not demonstrate decoded XMA or audible game sound.

Next work: bind the captured shader pair and its actual Xenos target/raster state to Vulkan, resume the guest, and extend only the next exercised graphics/resource contracts. No menu, playable build or game scene has been produced.
